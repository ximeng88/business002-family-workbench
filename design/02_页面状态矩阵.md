## 0. 先定义"离线"这件事（重要前置）

本项目是 **PWA + IndexedDB，无业务后端**。这意味着：

> **离线不是异常态，是常态。** 断网时功能和联网时**完全一致**，不应该出现任何"网络不可用"的提示。

因此本矩阵中"离线"一栏不描述业务降级，只描述**唯一真正与网络有关的三个场景**：

| 场景 | 现象 | 设计应对 |
|---|---|---|
| O1 首次访问且无缓存 | Service Worker 尚未缓存完成，或缓存被浏览器清理后首次打开且断网 | 明确提示**需要联网首次打开**：「第一次打开需要联网一下，之后就不用联网了」+ 「重试」。文案不归因为"网络错误"，只说明"还没下载好" |
| O2 版本更新 | 检测到新版本已下载完成 | 底部一条轻提示条「有新版本，下次打开时生效」，不强制刷新（强制刷新会丢用户当前操作） |
| O3 应用未安装 | 用浏览器直接访问 | 家长端设置页显示「安装到桌面」入口（仅此处，不弹窗骚扰） |

**明确禁止的两类文案**（这是产品级红线，不是风格偏好）：

1. ❌ 「离线模式」「同步中」「正在重新连接」「网络错误，请检查网络」——这些在有后端的应用里才有意义，出现在本产品里是设计错误。
2. ❌ **任何"离线可用 = 数据不会丢"的宣传性表达**，如「离线可用，数据永久保存」「本地存储，绝不丢失」。事实是：离线可用只解决"能不能打开"，不解决"数据会不会被清"。数据安全只由"导出备份 + 持久化存储"两件事保障，任何界面不得把前者包装成后者。

> 完整的分场景处理（含存储不可用）见第 8.2 节。

## 1. 五态定义（全站统一）

| 状态 | 定义 | 视觉规格 |
|---|---|---|
| **默认（Ready）** | 有数据，正常可操作 | 正常渲染 |
| **空态（Empty）** | 该页面结构成立但无数据 | 居中插图（或图标）+ 一句解释 + **一个下一步按钮**（禁止只有"返回"） |
| **加载（Loading）** | 本地读取中 | 本地 Dexie 读取 < 100ms，**页面级不使用骨架屏**；仅在「导出 / 导入 / 申请持久化 / 审核提交」这类跨进程动作上使用按钮内 loading |
| **异常（Error）** | IndexedDB 打开失败、事务失败、配额不足、导入文件损坏 | 分级处理（见第 8 节） |
| **离线（Offline）** | 见第 0 节 | 无业务降级 |

**关于"不用骨架屏"的设计判断**：本地数据库读取通常在几十毫秒内完成。给一个 40ms 的操作加骨架屏，只会造成"闪一下"的视觉噪音，比直接渲染更差。这条规则对 Trae 的实现有直接约束：**不要在页面级加载态上过度设计**。

**决策状态标注（全文档统一，口径见 `00` §8）**：本文件中凡出现「**已确认**」= D1（Owner 已决定，必须照做）；「**待裁决 / 待 Owner 确认 / D2**」= 方案已写但未获批准，可按方案实现但需保留可换空间；「**V2 / 后续版本**」= D3（第一版不实现）。
当前属于 D2 的界面条款：§7.1 备份提醒阈值（Q-01）、§2.9 与 §8.7 删除流程（G-05）、§3 提交后是否含附件内容（G-01）。**QA 不得把 D2 条款当作已冻结规则验收，也不得因它与 PRD 原文不同就判为错误。**

### 2.2 P-C2 今日任务

| 状态 | 表现 |
|---|---|
| 默认 | 问候 + 进度 `3/5 做完啦` + 四个分区（需修改 / 要做的 / 等确认 / 已完成折叠） |
| 空态（今天无任务） | 插图 + 「今天没有任务，去陪宠物玩吧」+ 按钮「去找宠物」→ P-C3 |
| 特殊（有往期未完成） | 「要做的」区中，今天的任务在上、往期任务在下（带灰色「补交」标签，副标题「昨天的」）。<br>**折叠态：最多展示 3 条，区底部固定一行 `还有 N 条逾期任务，展开查看`（N ≥ 1 必现），点击展开，展开后此行变「收起」。**<br>**禁止**只显示 3 条而让其余任务静默消失。<br>**折叠状态变化**：展开/收起 200ms 高度过渡，不跳页、不弹层；会话内记忆，冷启动恢复折叠。 |
| 空态（全部完成） | 进度区变为庆祝态：`5/5 全部做完啦` + 一句「今天很棒，等爸爸妈妈确认」+ 按钮「去看看宠物」 |
| 加载 | 无页面级 loading |
| 异常 | 任务读取失败 → 页内错误卡「任务暂时打不开」+ 「重试」（不清空已有界面，保留上次渲染结果） |
| 离线 | 无差异 |
| 部分异常 | 单条任务数据异常（缺字段）：该卡片显示"这条任务有点问题，请家长检查"，其他卡片正常 |

**分区显示规则（重要）**：某个分区为空时**整个分区隐藏**，不显示"暂无内容"。孩子端不应出现四个区全是"暂无"的界面。

### 2.4 P-C4 连续学习

| 状态 | 表现 |
|---|---|
| 默认 | 「连续 X 天」大数字 + 最近 7 天点阵 + 解释文案 |
| 空态（从未通过） | 大数字显示 `0`，文案「从今天开始，第一条通过的任务会点亮第一颗圆点」+ 按钮「去完成任务」→ P-C2 |
| 空态（连续中断） | 显示当前实际连续天数（可能为 1 或 0），**不加任何"可惜断了"的措辞**，只平铺事实 |
| 加载 | 无 |
| 异常 | 读取失败 → 页内错误卡 + 重试 |
| 离线 | 无差异 |
| 特殊 | 点某天圆点 → 轻量弹层列出当天通过的任务名与星星 |

**点阵规格**：7 个圆点等距横排，今天在最右。已达成 = 实心（孩子端主色）；未达成 = 空心描边（中性灰）；今天未达成 = 空心 + 一圈虚线。**不显示日期数字，不显示星期，不做坐标轴。**

| **删除 · 验 PIN** | 全屏弹层：「请输入家长 PIN」+ 4 位键盘；「用恢复码」兜底。连续 5 次错误 → 提示用恢复码（不锁定） |
| **删除 · 范围说明** | 全屏弹层（不可下滑关闭、遮罩不可点关闭）：标题「删除全部家庭数据」+ 四条范围说明（见 `01` §3.6）+ 勾选框「我知道删除后无法找回」+ 按钮 `取消` / `永久删除`（**勾选前 `永久删除` 为禁用态**） |
| **删除 · 执行中** | 全屏「正在删除…」，无按钮、不可交互、不可返回（防"删一半退出"） |
| **删除 · 成功** | 全屏「已经删除了」+「现在可以从头开始设置」→ 自动重新加载 → P-C1 空家庭态（「还没有小朋友，请家长先设置」） |
| **删除 · 失败** | 全屏「这次没删干净」+ 原因（空间异常/被浏览器中断/其他）+ 一句**当前数据状态**（见 §8.7 的状态判定）+ 按钮 `再试一次` / `取消`。**禁止出现"已删除"字样** |
| 离线 | 无差异（导出导入都是本地文件） |

## 3. 任务四状态 · 双端视觉对照

这是本产品的核心状态语言，必须两端严格对齐。

| 状态 | 值（建议） | 孩子端文案 | 孩子端视觉 | 可执行动作 |
|---|---|---|---|---|
| 待完成 | `todo` | 任务名 + 「我做完啦」 | 白卡，左侧图标彩色，主按钮实心（孩子端主色） | 提交 |
| 待家长确认 | `submitted` | 「等爸爸妈妈看」 | 卡片降饱和（85% 不透明），主按钮变为**只读标签**"已交，等确认"，无点击 | 无（可展开看详情） |
| 已通过 | `approved` | 「已完成」 | 卡片浅绿底 + 左侧绿色对勾 + 星星数显示为已完成态 | 无 |
| 需修改 | `revision` | 「需要再改一下」+ 家长原因 | 卡片浅紫底 + 左侧紫色循环图标 + 展示原因文本 + 主按钮「我改好了」（文案区别于"我做完啦"） | 重新提交 |

| 状态 | 家长端文案 | 家长端视觉 | 可执行动作 |
|---|---|---|---|
| 待完成 | 「未完成」 | 灰字标签 | 无（不提供"我替他完成"） |
| 待家长确认 | 「待确认」 | 琥珀色标签 + 进入 P-P3 | 通过 / 需要再改一下 |
| 已通过 | 「已通过」 | 绿色标签 + 通过时间 | 无（**不提供"撤销通过"**，见 IR-09） |
| 需修改 | 「已退回」 | 紫色标签 + 退回原因摘要 | 无（等孩子重新提交） |

**颜色不得混用**：
- 绿色只表示"已通过/成功"；紫色只表示"需修改/再来一次"；琥珀只表示"等待中/需要注意"；灰色只表示"未开始/补交/停用"。
- **红色在孩子端完全禁用**（除系统级致命错误）。红色只允许出现在家长端的删除类操作。

**这张表只有四行，且必须永远是四行（Owner 决定 Q-15）**：
- 不新增"已放弃""已过期""已取消""请假"等第五状态；这些词也不得作为**标签**出现在卡片上（标签等于变相引入状态）。
- 孩子端不出现"我不想做了/放弃这条/跳过"的按钮或文字入口。
- 孩子做不到时，卡片就停在"待完成"。它不会变红、不会倒计时、不会被自动关闭；家长端看到的仍是"未完成"，处理方式只有：退回（若已提交）、停用模板（阻止以后再生成）。

## 4. 逾期补交的视觉标记

| 项 | 规格 |
|---|---|
| 触发条件 | 任务的应完成日期 **< 今天（按设备本地自然日比较，Q-14）**，且尚未通过（即 `todo` / `submitted` / `revision` 都可能带补交标记） |
| 截止语义 | `dueDate` 是**日期级**（如 `2026-11-19`），不是时刻：每日任务默认当天 23:59 截止，但判定只用"日期 < 今天"。**不显示具体时间、不做倒计时、不做"还有 3 小时"** |
| 标签形态 | 小号胶囊标签，文字「补交」，**灰底灰字**（`#F1F2F4` 底 / `#5C6370` 字），12px，位于任务名右侧 |
| 位置 | 孩子端任务卡、家长端任务明细、家长端待确认卡 |
| 承载位置（关键） | 孩子端 **P-C2「要做的」区**（与今天的任务同区，排在其后）；家长端 **P-P1 展开孩子明细**。若往期任务不在此承载，孩子将找不到可补交的入口 |
| **可发现性（关键）** | 折叠态必须在区底部显示 `还有 N 条逾期任务，展开查看`（N 为被折叠条数，N ≥ 1 必现），点击展开、再点「收起」。**禁止只显示 3 条让其余静默消失。** 入口位置、交互时长见 `01_信息架构.md` §2.2.1 |
| 禁止事项 | ❌ 红色 ❌ 感叹号图标 ❌ "已逾期 3 天"的红色倒计时 ❌ 逾期天数的数字强调 ❌ 任何"你迟到了"的措辞 ❌ 静默折叠 |
| 允许的辅助文案 | 孩子端卡片可显示「昨天的」，仅此一句 |
| 补交规则（Owner 决定 Q-04） | **全局允许补交**，不设按任务开关。补交审核通过后，**正常获得该任务的全部原定星星与经验**（不打折、不延迟发放）。 |
| 补交流程完整性 | 与当天任务走**完全相同**的状态机：提交 → 待家长确认 → 家长审核 → 奖励发放。不简化、不跳过审核、不改奖励。 |
| 连续记录影响 | **补交通过 → 记在"今天"，不回填昨天**（K17、IR-20）。即使原定日期那天因此仍是空的，也不追认。孩子端连续页需有说明文案。 |
| **折叠与审核的关系** | 折叠是**纯展示层状态**，不写入数据、不作为查询条件。孩子提交了折叠区内的任务，家长端 P-P3 **必须**收到该提交，并在列表中带同样的「补交」标签（IR-31）。 |
| 长期未处理 | 超过 7 天未通过的任务，家长端明细里加一行浅灰说明「这条已经放了 7 天」，仅提示不加压 |

**为什么用灰不用红**：逾期在小学生学习场景中极高频且多为家长安排问题（作业多、临时外出），红色会把"家庭协作的正常波动"渲染成"孩子的过失"。灰色表达"这件事晚了"，不表达"你做错了"。

## 7. 备份过期提醒的视觉层级

**位置约束（K15）**：只在 **P-P1 孩子列表页顶部吸顶**显示。孩子端永不显示（备份是家长的责任，不能让孩子承担数据焦虑）。

### 7.1 分级

> **阈值是设计建议（Q-01 待 Owner 确认），不是冻结规则。** 下表的分级可按裁决结果整体替换，实现时阈值必须是常量。

| 级别 | 触发条件 | 视觉 | 文案 | 动作 |
|---|---|---|---|---|
| L0 正常 | 距上次导出 ≤ 7 天 | **不显示** | — | — |
| L1 提醒 | 距上次导出 8~14 天 | 浅琥珀条（`#FDF3E2` 底 / `#B4711A` 字），高 44px，左侧时钟图标 | 「已经 10 天没备份了」 | 「去备份」→ P-P5 备份区 |
| L2 强提醒 | 距上次导出 ≥ 15 天，**或从未导出过** | 深琥珀条（`#FBE7C6` 底 / `#8A5300` 字），高 56px，左侧警告图标，两行文案 | 主「数据只存在这台设备上」<br>次「清理浏览器可能让它消失，建议现在备份」 | 「立即导出」（主按钮，直接调起导出） |
| L3 异常 | 检测到存储未持久化 | 与 L2 同级但额外显示一行 | 「浏览器没有承诺保留数据」 | 「申请保留」→ 触发持久化申请 |

### 7.2 交互细则

- 提醒条**不可手动永久关闭**（可以关闭当次，但下次进入首页仍显示）。理由：这是唯一的数据保命提示，允许永久关闭等于允许用户丢掉孩子的全部记录。
- 关闭当次后，同一会话内不再出现；重新打开应用后恢复。
- 导出成功后立即重算：若变为 L0，条带以 200ms 淡出消失，并给一条轻提示「备份好了」。
- 颜色禁用纯红。琥珀色表达"值得注意"，红色表达"危险"，此处的真实风险是"可能丢数据"而非"已经出错"，用琥珀更准确也更不惊扰。

### 7.3 与 `PRD_v1.3.md` §11.2 的差异（G-03，待裁决）

| 项 | PRD 原文 | 本设计 | 差异性质 |
|---|---|---|---|
| 是否常驻显示 | "家长端首页**必须持续显示**备份状态" | ≤7 天不显示（L0） | 冲突 |
| 不足 7 天的内容 | "显示上次备份日期" | 不显示 | 冲突 |
| 达到 7 天的文案 | "已经 7 天没有备份了" | 拆成 8–14 天 L1 / ≥15 天 L2 两级 | 细化，非冲突 |

**处置**：本轮**不改**本节分级（改了就等于替 Owner 裁决）。请 Owner 明确：是"常驻显示 + 两级提醒"，还是"按现设计不打扰"。若定为常驻，改法是：L0 状态下加一条**最轻**的常驻文字（如 `上次备份 11月16日`，无底色无图标），L1/L2 保持现有视觉层级。

## 8. 恢复码与异常兜底

### 8.1 恢复码流程（"请抄下来"必须显式）

| 阶段 | 规格 |
|---|---|
| 触发 | ① 首次设置家长 PIN 成功后 ② 在 P-P5「重新生成恢复码」 |
| 展示 | **全屏弹层**（不可下滑关闭，不可点遮罩关闭），显示 12 位恢复码，用等宽字体、分组显示（`AB3D-7K9M-2QX4`），字号 24px |
| 显式提示 | 弹层内固定文案（不可省略、不可折叠）：<br>**「请抄下来」**（20px 加粗，主色）<br>「这个码只有现在能看到，忘记 PIN 时只能靠它。截屏或写在纸上，别只留在手机里。」 |
| 强制确认 | 底部勾选框：`我已经抄写好了` —— **未勾选时「完成」按钮禁用** |
| 二次机会 | 勾选后可点「再看一次」，返回展示态 |
| 关闭后 | 该恢复码永不再显示明文，设置页仅显示「已于 X 月 X 日生成」，提供「重新生成」（会作废旧码，需二次确认） |
| 找回流程 | 家长 PIN 输入页「忘记 PIN」→ 输入恢复码 → 校验通过 → 设置新 PIN → 展示新恢复码（同上述流程） |
| 校验失败 | 「这个码不对，再看看纸上那一行」（不用"错误""失败"等词） |

**文案红线**：不得出现"加密""安全""保护隐私"。正确表达是"这是找回的办法"，而不是"这是安全措施"。

### 8.2 全局异常与存储场景（六个场景，逐条定行为）

本表是"异常"这一态的唯一口径。**注意：离线不在此表产生业务降级**——断网本身不构成异常。

| # | 场景 | 界面行为 | 级别 | 文案基调 |
|---|---|---|---|---|
| 1 | **正常离线使用**（应用已缓存、IndexedDB 正常） | 功能**完全可用**，与联网时无任何差别。**不显示任何"网络"相关提示**（无横幅、无图标、无灰条） | — | 不出现"网络"二字 |
| 2 | **首次访问但无缓存**（断网且 SW 未装好） | 全屏说明页：「第一次打开需要联网一下，之后就不用联网了」+ 「重试」按钮。**不进入业务界面**（此时确实没有界面可进） | E3-a | 说明"还没下载好"，不说"网络错误" |
| 3 | **SW 缓存不可用 / 资源加载失败**（缓存被清、资源 404、更新中断） | 全屏或页内提示：「页面没加载完整」+ 「重新打开」为主、「刷新」为次。**不归因为"网络错误"**，不提"离线"，不显示网络状态图标 | E3-b | 「重新打开试试」，不写"网络异常" |
| 4 | **IndexedDB 不可用或读取失败** | **阻止进入业务界面**，显示全屏数据异常页（详见 8.3）。读取局部失败（个别记录）时降级为该页错误卡 + 重试，**不清空界面，也不把失败当成空列表**（IR-40）。状态全集与恢复流程见 8.5、8.6 | E3-c / E1 | 「数据好像打不开了」+「数据还在，别担心」 |
| 5 | **本地存储空间不足 / 写入失败** | **不静默失败**，且**先分诊再提示**：①事务性失败 → 可重试；②配额不足 → 重试必然失败，提示清理空间 + 导出；③浏览器策略拒绝 → 提示换环境，启动阶段的拒绝进 8.6.5 终止态（IR-33）。同时：写操作回滚并恢复原状（E2）+ 引导「导出备份」+ 家长端首页备份提醒升为 L2 | E2 / E4 | 给动作，不给恐吓 |
| 6 | **PWA 首次安装 / 版本更新** | 安装：仅在家长端 P-P5 提供「安装到桌面」入口（不弹窗、不拦截）；更新：检测到新版本已就绪 → 底部轻提示「有新版本，下次打开时生效」（不强制刷新，避免丢当前操作） | — | 提示存在，不打断 |

**三条通用底线**：

1. 任何异常都必须落到上表某一格，**不允许有未定义的失败路径**（IR-30）。
2. 任何异常文案都不得出现技术词（`IndexedDB` / `QuotaExceededError` / `Transaction` / `Service Worker` / `404`）。
3. 任何异常都**不得**被描述成"数据已丢失"，除非确实需要用户从备份恢复（此时须明确说"可以从备份恢复"）。

### 8.3 IndexedDB 不可用时的界面行为（明确结论）

**结论：阻止进入业务界面，不降级为"只读模式"。**

这是本次修订中被明确要求给出结论的一项，理由必须写清：

| 为什么不能做成"只读降级" | 说明 |
|---|---|
| 技术上没有可读的内容 | 数据库打不开 = 一条记录都读不到。所谓"只读模式"只会渲染出一个**全空的界面**（0 个孩子、0 条任务、0 颗星星） |
| 空界面比报错更伤害信任 | 家长看到"朵朵 0 颗星星、没有任何任务"，第一反应是"数据被清空了"，而不是"数据库打不开"。这会直接引发恐慌，且可能促使他去做错误的补救动作（比如导错文件覆盖） |
| 产品在只读态下没有价值 | 提交、审核、兑换全部依赖写入。只读的孩子端只能看空列表，比明确报错更没有意义 |

**分级处理**：

| 子场景 | 判定 | 行为 |
|---|---|---|
| E3-c1 数据库无法打开（被浏览器阻止、损坏、版本冲突） | 打开动作抛错 | **阻止进入**，全屏数据异常页（见下） |
| E3-c2 数据库可打开，但某个 store 读取失败 | 打开成功、查询抛错 | 降级为**该页错误卡**（E1）+ 重试，保留 Tab Bar，其他页可用 |
| E3-c3 数据库可打开，但写入事务失败 | 打开成功、写入抛错 | 按 E2 处理：操作回滚、按钮恢复、提示重试 |

**全屏数据异常页规格**：

| 元素 | 内容 |
|---|---|
| 图标 | 中性灰的文件图标（**不用红色感叹号**） |
| 主标题 | 「数据好像打不开了」 |
| 副文案 | 「你的记录应该还在，只是现在读不出来。先试试重新打开，不行可以从备份恢复。」 |
| 按钮 1（主） | 「重新打开」→ location.reload() |
| 按钮 2（次） | 「从备份恢复」→ 进入导入流程（IR-16），**这里必须允许在无数据库状态下选择文件** |
| 按钮 3（弱） | 「关掉其他标签页再试」→ 文字按钮，附一行说明「同时开多个页面有时会打不开」 |
| **禁止** | ❌ 显示 Tab Bar（不允许切到任何业务页）❌ 显示"0 个孩子/0 颗星星"的空数据界面 ❌ 提供"清空数据重来"按钮（等于引导用户销毁证据）❌ 用红色错误页 |

**为什么把"关掉其他标签页"放出来**：本地数据库在多标签页同时打开时容易出现版本升级冲突与阻塞，这是本项目最常见的 E3-c1 成因。把它写成一句可选提示，能解决相当一部分"打不开"，而成本只是三行字。

**关键补充（v0.3）：恢复不能依赖原数据库。** 本页的「从备份恢复」**不是**常规导入（常规导入假设库可用）。它必须走 §8.6 的独立恢复流程：临时内存校验 → 家长确认重建 → 建立新库 → 事务写入 → 结果校验 → 重新加载。

| 认识上的分界 | 说明 |
|---|---|
| "数据库打不开" ≠ "无法恢复" | 打不开的是**旧的库**；恢复是**新建一个库再把数据写进去**。两者不是同一件事 |
| 恢复失败 ≠ 备份文件有问题 | 文件可能完好，失败可能是空间不足或浏览器禁止建库。这两类失败的文案与出口必须分开（§8.6.5） |
| 重建失败 = 环境不可用 | 若确认重建后仍建不出库，说明这个浏览器环境不允许本应用存数据，进终止态，**不给无限重试** |

### 8.4 与"数据安全"表述的边界

必须再强调一次（与 §0 呼应）：

- 「离线可用」只承诺**能打开**，不承诺**数据不会丢**。
- 数据安全的真实保障只有两条：**持久化存储申请** + **导出备份**。界面上凡是提到"数据在本地很安全"的地方，都必须同时出现"记得定期导出"。
- 禁止任何界面把「无需联网」写成卖点式承诺，例如「不联网也不丢」「本地永久保存」。

**E3 文案要求（保留）**：不出现 "IndexedDB""QuotaExceededError""Transaction" 等技术词。家长看到的是「数据好像打不开了」，不是错误码。

### 8.5 IndexedDB 异常状态矩阵（完整状态全集）

本节把"数据库相关异常"穷举成三组状态，**任何一条实现路径都必须能落到其中一格**，不存在"未定义"。

**I 组：打开与读取（启动阶段）**

| 编号 | 场景 | 判定 | 界面 | 数据结果 | 出口 |
|---|---|---|---|---|---|
| **I1** | 浏览器不支持 / 禁用 IndexedDB、隐私模式禁止站点数据 | 打开库的动作直接不可用 | **终止态页**（§8.6.5） | 无库，无法写入 | 复制诊断信息 / 看常见原因；**无重试** |
| **I2** | 库能打开，但某张表/某个查询读取失败 | 打开成功、查询抛错 | **页内错误卡**（该区块）+ 其他区块正常 | 数据不变 | 重新读取 / 重新加载 / 从备份恢复（§8.6） |
| **I3** | 库打不开（损坏、多标签页版本冲突、被策略阻止） | 打开抛错 | **全屏数据异常页**（§8.3） | 未知，但不删不改 | 重新打开 / 关掉其他标签页 / 从备份恢复 |
| **I4** | 数据库版本升级失败 | 升级事务中止 | 全屏异常页 + 说明「数据好像没能升级」 | 旧数据可能仍在，**不得自动降级或删库** | 重新打开 / 从备份恢复 |
| **I5** | 库能打开但完全为空（曾用过、被浏览器清了站点数据） | 0 孩子、0 流水 | **空家庭态**（不是异常页） | 已丢失（不可判定原因） | 「请家长来设置」；家长端另给一句轻提示「如果之前用过，可能是浏览器清掉了数据，可以从备份恢复」 |

> **I5 为什么不算异常**：应用无法区分"第一次安装"和"被清空"，两者都是空库。把它渲染成错误页会让新用户一进门就以为坏了。因此按空态处理，但**在家长端提供一句恢复提示**，不做弹窗、不做红色。

**W 组：写入（操作阶段）**

| 编号 | 场景 | 判定 | 界面 | 数据结果 | 出口 |
|---|---|---|---|---|---|
| **W1** | 事务性失败（约束冲突、中止、并发条件不满足） | 事务回滚 | 操作控件恢复原状 + 顶部提示「这次没保存上，再点一次」 | **零变化** | 手动重试 |
| **W2** | 配额不足 / 空间不够 | `QuotaExceeded` 一类 | 回滚 + 提示「手机空间不够了」+ 「导出备份」引导 + 备份提醒升 L2 | **零变化** | 清理空间 / 导出后换设备；**不鼓励反复重试** |
| **W3** | 浏览器策略拒绝写入（只读、策略限制） | 写入持续失败 | 回滚 + 提示「这个浏览器现在不让保存」+ 换环境建议 | **零变化** | 换浏览器/退出隐私模式；启动阶段即拒 → §8.6.5 终止态 |

**B 组：备份文件（恢复阶段，全部发生在写库之前）**

| 编号 | 场景 | 界面提示（人话） | 数据结果 | 出口 |
|---|---|---|---|---|
| **B1** | 文件无法读取（0 字节/被截断/无权限） | 「这个文件打不开，可能没下载完整」 | 现有数据不变 | 换一个文件 |
| **B2** | JSON 格式错误 | 「这个文件不是本应用导出的备份」 | 不变 | 换一个文件 |
| **B3** | 版本不兼容 | 「这个备份是别的版本做的，当前版本打不开」 | 不变 | 换一个文件 / 取消 |
| **B4** | 必需字段缺失 / 类型错误 | 「这个备份缺了一部分内容，恢复出来会不完整」 | 不变 | 换一个文件 |
| **B5** | 附件/图片 Blob 不完整 | 「备份里的照片有一部分读不出来」 | 不变 | 换一个文件 / 「仍然恢复（不含照片）」——**仅当主体完整时提供**且按钮写明后果 |
| **B6** | 数据校验失败（引用断裂、孤儿记录） | 「这个备份里的记录对不上，不敢直接恢复」 | 不变 | 换一个文件 |
| **B7** | 规模异常（记录数/单条长度/总大小不合理） | 「这个文件大得不正常」 | 不变 | 换一个文件 |

> **B 组的铁律**：所有 B 类失败都发生在**写库之前**，因此**永远不会**影响现有可用数据，也**永远不删除用户文件**。

### 8.6 从"数据库打不开"到"恢复成功"的完整流程

#### 8.6.1 流程总览

```
数据库打不开（I3 / I4）
      │
      ▼
全屏异常页「数据好像打不开了」
      │  点「从备份恢复」
      ▼
① 选文件（系统文件对话框）
      ▼
② 临时内存读取 + 校验（B1–B7 任一项不过 → 8.6.4 失败闭环，库不动）
      │  ＋ 大小与空间预检（只给风险提示，不阻止继续）
      ▼
③ 展示恢复摘要 + 二次确认（"这会重建本机数据库"）
      │  取消 → 回异常页
      ▼
④ 重建目标数据库 ──失败──▶ 8.6.5 终止态（环境不可用）
      ▼
⑤ 单事务写入全部数据 ──失败──▶ F2 恢复中断（"再试一次"/导出诊断）
      ▼
⑥ 校验恢复结果（**7 条判据**）──不符──▶ F2 恢复中断
      ▼
⑦ 写恢复元数据 → ⑧ 重新加载 → ⑨ 进入业务界面
```

#### 8.6.2 分步界面规格

| 步 | 界面 | 必须显示 | 禁止 |
|---|---|---|---|
| ① 选文件 | 系统文件选择器 | 仅允许选择备份文件类型；页面保持异常页不变 | ❌ 要求先"登录/建库"才能选文件 |
| ② 校验 | 全屏进度：「正在检查备份文件…」（不可交互） | 进度可感知（不必精确百分比）；超过预期时长给一句「还在检查，稍等」 | ❌ 边写边校验 ❌ 校验期间改动数据库 |
| ②b **大小与空间预检**（v0.4 新增） | 与 ② 同一进度页，末尾附一行结论（正常时不额外提示） | ①备份文件大小（如 `18.6 MB`）②可用空间是否**明显**低于所需（按"文件大小 × 安全系数"估）③空间紧张时给一行风险说明：「这台设备的空间可能不够，恢复有可能中途停下」。**必须说明这是估算，不是结论** | ❌ 把估算值说成"空间足够，可以放心" ❌ 用估算值阻止用户继续（可以由用户选择继续） ❌ 因为空间紧就自动放弃恢复 |
| ③ 摘要 + 确认 | 全屏弹层（不可下滑关闭，遮罩不可点关闭） | ①备份时间 ②备份版本 ③数据量：`2 个孩子 · 128 条任务 · 340 条星星记录` ④明确风险句：「恢复会重建这台设备上的本地数据库」⑤按钮 `取消` / `重建并恢复`（危险色，需二次点击） | ❌ 未确认就重建 ❌ 把"重建"说成"合并" ❌ 隐藏将被重建的事实 |
| ④ 重建 | 全屏：「正在准备本地空间…」 | — | ❌ 重建失败后继续写入 ❌ 自动重试重建 |
| ⑤ 写入 | 全屏进度：「正在恢复数据（3/7）」 | 分区进度（按数据类别） | ❌ 分批提交 ❌ 失败后留下半成品 |
| ⑥ 校验 | 全屏：「正在核对…」 | — | ❌ 跳过校验 ❌ 数量不符仍判成功 |
| ⑦ 元数据 | 无独立界面 | 记录"上次恢复时间"；**不改**"上次导出时间" | ❌ 把恢复当作备份，导致备份提醒归零 |
| ⑧ 重载 | 「恢复好了，正在重新打开」 | 摘要一行：`来自 11月18日 的备份 · 2 个孩子 · 128 条任务` | ❌ 显示"导入成功"后仍停在异常页 |
| ⑨ 收尾 | 正常业务界面 | 首次进入轻提示一次「已从 X 月 X 日的备份恢复」 | ❌ 反复提示 ❌ 再弹一次"是否导入" |

#### 8.6.3 恢复成功的判定标准（**7 条，缺一即失败**）

> v0.4 升级说明：v0.3 的 5 条里"数量一致"只查了总量、"关键值一致"混着说，容易实现成"总记录数对就过"。本轮拆成**分表计数 + 关联完整性 + 汇总正确性 + 宠物经验 + 附件可读**五项，逐项可验证。

| # | 判据 | 判据的具体做法 | 反例（这样判会漏） |
|---|---|---|---|
| 1 | **写入无异常** | 第 ⑤ 步事务完整提交，无中止、无配额错误 | 只看"没抛错"不看提交结果 |
| 2 | **库可重新打开** | 写完关闭，再重开一次目标库，能打开且版本正确 | 写进去但打不开，仍报成功 |
| 3 | **分表记录数一致** | **逐表**比对（孩子 / 模板 / 任务实例 / 审核记录 / 积分流水 / 宠物经验 / 连续记录 / 奖励 / 设置），每张都与备份摘要相等 | 只比"总记录数"（A 表多 2 条、B 表少 2 条，总数一样却已错） |
| 4 | **关键关联完整** | 任务引用的孩子存在；流水引用的孩子存在；兑换/奖励引用存在；模板引用存在；**无孤儿记录、无悬空外键**；主键无重复 | 只数条目不查引用（恢复出"有 128 条任务但 3 条找不到主人"） |
| 5 | **积分汇总正确** | 每个孩子的**星星合计 = 该孩子流水变动值之和**（与备份中该合计相等）；流水条数一致；无负余额异常跳变 | 只比条数（条数对但某条正负号写反） |
| 6 | **宠物经验完整** | 每个孩子的等级、当前经验、升级所需经验与备份一致；经验流水条数与备份一致；**经验与积分各自独立核对**（不得用星星合计代替经验） | 只查等级不查经验，或反过来用星星验证经验（K11 明确两者分开） |
| 7 | **附件可读**（⚠️ **依赖 G-01 裁决**） | 若备份含照片等 Blob：**数量一致 + 总字节数与备份元数据一致 + 随机抽样可解码读取**（不是"字节存在"就算可读） | 只数 Blob 个数；或只读长度不试解码 |

| 项 | 规则 |
|---|---|
| 判据 7 的生效条件 | **G-01 未裁决前，本条按"规格已写、实现待定"处理**：若第一版最终不含附件，本条自动降为"不适用"并记录原因；若含附件，本条是**必须项**，不得因为"照片不是核心数据"而跳过 |
| 失败处理 | 任一条不过 → 一律按 F2 处理，界面必须说明"本机现在没有可用的数据"，**不得暗示部分成功**、不得"先把能用的用起来" |
| 禁止 | ❌ 只判"事务没报错" ❌ 只比总量 ❌ 用星星合计代替经验核对 ❌ 附件只数个数 ❌ 7 条里任一条"跳过不查"却仍显示「恢复好了」 |

**关于 v0.3 的"抽样可读"**：它没有被删掉，而是并入 §3 与 §5 的核对动作里（数完条目必须随机抽几条真正读出来看字段完整），因为"抽样"不是一条独立判据，而是**验证方法**。单列成第 8 条会让实现者以为"数完数就够了、抽样可以不做"。

#### 8.6.4 备份文件校验失败的闭环（B1–B7）

| 环节 | 规格 |
|---|---|
| 展示位置 | 弹层（可关闭），保留已选文件名 + 失败原因一行 |
| 主按钮 | `换一个文件` → **直接重新打开文件选择器**，不需要退回首页再进来 |
| 次按钮 | `取消` → 回异常页（异常恢复场景）或回 P-P5（正常导入场景） |
| 现有数据 | **零影响**（校验阶段不触碰业务库） |
| 备份文件 | **不删除、不移动、不改名**；用户可在任何设备再次尝试 |
| 重试 | 只有用户主动换文件才算重试；**不做自动重新解析** |
| 禁止 | ❌ 把 7 类原因合并成一句"导入失败" ❌ 校验失败后清空或"重置"数据库 ❌ 提示用户"再导一次试试"而不说原因 |

#### 8.6.5 终止态页（确认重建后仍建不出库）

**这是本次要求补的终止状态：它不属于备份文件问题，不能归因为"导入失败请重试"。**

| 元素 | 内容 |
|---|---|
| 图标 | 中性灰「设备/浏览器」图标（非红色感叹号） |
| 标题 | 「这个浏览器现在用不了本应用」 |
| 正文 1 | 「不是备份文件的问题——文件已经检查过了。是这台设备上的浏览器不允许本应用保存数据。」 |
| 正文 2 | 「你的备份文件还在。换一个浏览器或换一台设备打开本应用，再用同一个文件恢复就可以。」 |
| 诊断信息（可折叠） | 环境标识 / 失败阶段（建库）/ 错误类别（仅类别不给堆栈）/ 时间 / 应用版本 |
| 主按钮 | 「复制诊断信息」 |
| 次按钮（弱） | 「可能是什么原因？」→ 展开：隐私/无痕模式、浏览器禁用了站点数据、企业或系统策略限制、存储空间长期不足 |
| **禁止** | ❌ 提供「重试」作为主按钮（同环境重试必然再失败）❌ 提供自动重试循环 ❌ 出现"恢复成功/部分恢复成功" ❌ 引导删除备份文件 ❌ 提供"先用空数据"入口 ❌ 显示"网络错误" |

**判定依据**：只看第 ④ 步（重建目标库）是否失败，与文件校验无关。若文件校验就没过，那属于 B 组，不是终止态。

**必须补充的一条边界（v0.4）：终止的是"本次流程"，不是"永久权利"。**

| 项 | 规则 |
|---|---|
| 终止范围 | 终止的是**当前这一次**恢复流程。不提供"在同一页面反复重试"的入口，因为同环境重试必然再失败 |
| 恢复机会是否保留 | **保留**。用户修好环境后（关掉无痕模式、允许站点数据、清理空间、换浏览器/设备），**重新打开应用**会重新从 I 组判定开始：库若能打开 → 正常业务界面；仍打不开 → 又回到全屏异常页，并可再次选择「从备份恢复」 |
| 界面必须写清 | 「你的备份文件还在。换一个浏览器或换一台设备打开本应用，再用同一个文件恢复就可以。」——这句话的作用就是告诉用户"权利还在、文件还在" |
| 禁止 | ❌ 写成"永久无法恢复"/"数据已丢失" ❌ 隐藏备份文件仍然有效的事实 ❌ 在终止页放一个"我已修复，立即重试"的按钮（同环境点它只会再失败一次，制造"彻底坏了"的错觉） |

#### 8.6.6 三种失败类型的对照（F1 / F2 / F3）

| 类型 | 触发 | 定性 | 界面 | 可否重试 | 数据现状 |
|---|---|---|---|---|---|
| **F1 文件问题** | B1–B7 | 文件的问题 | 弹层 + 具体原因 | 可（换文件） | 现有数据完好 |
| **F2 恢复中断** | 写入/校验失败、配额不足 | 过程的问题 | 全屏「这次没恢复成功」+「本机现在没有可用的数据」 | 可（手动，重新选文件） | 无可用库，需重来 |
| **F3 环境不可用** | 重建目标库失败 | 环境的问题 | 终止态页（§8.6.5） | **本次不可**（不提供主重试）；**环境修复后重开应用可再次尝试** | 无库；备份文件仍完好 |

#### 8.6.7 恢复流程的禁止事项（汇总）

- ❌ 因为"数据库打不开"就把恢复入口关掉（那是用户唯一的出路）。
- ❌ 用"新建空库 + 提示成功"冒充恢复。
- ❌ 校验未通过就重建；未确认就重建。
- ❌ 恢复过程中删除、移动用户的备份文件。
- ❌ 把 F1/F2/F3 三类失败混用一套文案。
- ❌ 在 F3 上提供无限重试或"稍后自动恢复"。
- ❌ 恢复成功后把"上次导出时间"改成现在。
- ❌ **把浏览器报告的"可用空间估算"当成写入成功的保证**（估算不准是常态：浏览器给的是配额上限而非实际可用，且写入过程中其他标签页可能占掉空间）。文案只能写"看起来够用/可能不够"，**不得**写"空间足够，可以放心恢复"。
- ❌ **恢复过程中留下一个"能被正常业务界面打开"的半成品库**（写入失败后若库还在、带着一部分数据，必须先清除或隔离，否则家长会看到一个残缺的家庭并以为是真的）。
- ❌ **把"恢复备份"与"删除全部家庭数据"合成一个操作或一个按钮**（`02` §8.7 / `03` IR-41）。

### 8.7 删除全部家庭数据的状态（G-05 · D2 待确认）

> 依据 `PRD_v1.3.md` §11.6。入口在 P-P5「危险操作」分组（`01` §3.5 / §3.6），**不属于 §8.5 的 IndexedDB 异常**，也不走 §8.6 的恢复流程。

**DEL 组：删除流程的 6 种界面状态**

| 编号 | 状态 | 判定 | 界面 | 数据结果 | 出口 |
|---|---|---|---|---|---|
| **DEL-1** | 未触发 | 家长停留在 P-P5 | 底部一行灰色文字按钮「删除全部家庭数据」+ 说明「删除后无法恢复」 | 不变 | 点击 → DEL-2 |
| **DEL-2** | 等待验 PIN | 已点入口 | 全屏弹层「请输入家长 PIN」+ 4 位键盘 + 「用恢复码」 | 不变 | 正确 → DEL-3；取消 → DEL-1；5 次错 → 提示用恢复码 |
| **DEL-3** | 等待二次确认 | PIN 通过 | 全屏弹层：标题 + 四条范围说明 + 勾选框 + `取消` / `永久删除`（未勾选为禁用） | 不变 | 确认 → DEL-4；取消 → DEL-1 |
| **DEL-4** | 执行中 | 已确认 | 全屏「正在删除…」，无按钮、不可返回 | 事务进行中 | 自动 → DEL-5 / DEL-6 |
| **DEL-5** | 成功 | 清空事务提交成功，且重开库校验为空 | 全屏「已经删除了」+「现在可以从头开始设置」 | **本机无任何家庭数据**；家长 PIN 与恢复码一并清除 | 重新加载 → P-C1 空家庭态 → 家长首次设置 |
| **DEL-6** | 失败 | 事务中止 / 被浏览器中断 / 部分表清空 | 全屏「这次没删干净」+ 原因 + **当前数据状态说明** | 见下方"失败后的数据状态判定" | `再试一次` / `取消` |

**失败后的数据状态判定（DEL-6 必须说清，不允许含糊）**

| 实际结果 | 界面必须怎么说 |
|---|---|
| 事务完整回滚（数据仍是删除前那样） | 「没删掉，数据还是原来的」——这是最理想的一种失败 |
| 已清空一部分，无法确知删了什么 | 「有一部分删掉了，有一部分还在。建议先导出备份，再重试一次」+ **禁止**把界面渲染成正常家庭（不清空列表、不假装完整） |
| 无法读取当前状态（库本身出问题） | 转 §8.3 全屏异常页，**不得**显示"已删除" |

> **三种失败都不许显示"删除成功"**，也都不许自动重试清空。中间态家庭（部分删）必须显式标注为"不完整"，否则家长会把它当成真实数据继续用。

**删除范围（写死的清单，不允许实现时自行缩减）**

| 类别 | 是否删除 | 说明 |
|---|---|---|
| 孩子资料（头像/昵称/PIN） | **删** | 含孩子 PIN |
| 任务模板、任务实例、审核记录 | **删** | 历史任务一并删除（K18 的例外路径之一，必须由家长显式触发） |
| 积分流水、奖励设置、兑换申请 | **删** | 余额随流水消失 |
| 宠物等级与经验 | **删** | — |
| 连续学习记录 | **删** | — |
| 家长 PIN、恢复码、家庭设置 | **删** | 否则会留下"旧家庭仍然有效"的错觉（PRD §11.6 明确要求） |
| 照片等附件 Blob（若 G-01 裁决含附件） | **删** | 与任务一并删除，不得只删记录留下二进制 |
| 用户在设备文件系统上的备份文件 | **不删** | 应用无权也不应触碰；文案必须说明"你保存的备份文件还在" |
| 浏览器缓存 / Service Worker / 应用本身 | **不删** | 删的是家庭数据，不是卸载应用；删除后应用应能直接重新初始化 |

**与"恢复备份"的区别（两者不得混为一项操作）**

| 维度 | 删除全部家庭数据 | 从备份恢复 |
|---|---|---|
| 目的 | 清空，从零开始 | 找回，把数据写回来 |
| 前置 | 库**可用**（在 P-P5 里） | 库**可能不可用**（异常页也能进） |
| 验证 | PIN 重验 + 勾选确认 | 文件校验 7 项 + 摘要确认 |
| 结果 | 空家庭 | 有数据的业务界面 |
| 能否组合 | **禁止**做成"删除并恢复"一个按钮；恢复必须在删除完成后**另行发起** | 同左 |

**禁止事项**

- ❌ 删除时顺带删除用户的备份文件，或提示"备份文件已一并删除"。
- ❌ 删除失败却显示成功；或失败后不说明当前数据状态。
- ❌ 只删孩子资料而遗留任务、流水、宠物经验、附件（"删了孩子但星星还在"）。
- ❌ 把删除与恢复做成同一条流程、同一个按钮、同一段文案。
- ❌ 在数据库异常页/终止态页提供删除或清空入口（§8.3 已有禁令，此处再确认一次）。
- ❌ 删除后不重新初始化，停在半空界面（必须落到 P-C1 空家庭态）。

| 成功 | 关闭弹层 + 「价格改好了，孩子端已经是 13 颗」；列表与孩子端同步 | 已写入 |
| 失败 | 弹层不关 + 「这次没保存成功，再点一次」；已填数字保留 | 仍为旧价 |

**已提交的申请不受影响**：改价只影响之后的展示与新申请；审核金额仍取 `costSnapshot`（IR-11 / IR-11A 不变）。

### 10.4 选择伙伴（O-9）

| 状态 | 表现 |
|---|---|
| 首次进入（从未选过） | 整页即选择页，无返回；标题「选一个你的伙伴」；**没有"跳过"**（必须先选一个才能进入宠物页） |
| 再次进入 | 覆盖层形式，标题「换一个伙伴」；当前宠物标「现在这位」，选中态默认落在它上面 |
| 切换中 | 点「就选它」后按钮「正在换…」，卡片不可再点 |
| 成功 | 关闭覆盖层，宠物区整体重绘；**等级 / 经验 / 经验条 / 收藏 / 当前穿戴一个都不变**；不播庆祝动效（换伙伴不是升级） |
| 失败 | 覆盖层不关 + 「这次没换成，再点一次」；仍是原宠物 |
| 素材缺失（某只 SVG 未加载） | 该卡片显示灰底占位 + 「这只还没准备好」，**不可选**，其余四只正常可选；不整页报错 |
| 只有 1 只可用 | 仍显示选择页（说明当前只有一只），主按钮「就选它」；不隐藏入口 |

### 10.5 三个通用约束（新增，适用于本节所有动作）

1. **提交期间只禁用相关控件**，不整页 loading、不弹全屏遮罩——这些动作都是百毫秒级。
2. **失败一律保留用户已填内容**（昵称、积分、裁剪位置），让人"再点一次"就成功，而不是重填。
3. **任何一处图片失败都不允许出现裂图或空白头像**，必须回落到预设头像或灰底占位。
