**三个结构性事实**：

1. **身份选择是门，不是 Tab。** 它是唯一一个"孩子端与家长端的共同上游"。进去之后两端各自独立，互不交叉——孩子端里没有家长页面入口（除右上角小字），家长端里不模拟孩子视角。
2. **家长端与孩子端不共享 Tab Bar。** 切换端必须经过 PIN（家长）或身份选择（孩子），这是产品规则，不是技术限制。
3. **家长入口在两端的同一位置**（右上角），位置固定、视觉权重低（12px 灰色文字），避免孩子好奇点进去，也方便家长随时切。

## 2. 孩子端 IA

### 2.1 P-C1 身份选择（入口门）

| 项 | 内容 |
|---|---|
| 页面职责 | 让家里任何一个孩子在一屏内认出自己并进入 |
| 布局结构 | 标题「今天是谁呀？」→ 头像墙（1~4 个孩子，网格 2 列）→ 每个头像下方昵称 |
| 核心操作 | 点自己的头像卡（整卡可点） |
| 分支 | 该孩子设了 PIN → 弹出 4 位数字键盘层；未设 PIN → 直接进入 P-C2 |
| 出口 | ① 进入 P-C2 今日任务 ② 右上角「家长」→ 家长 PIN → 进入 P-P1 |
| 刻意不做的 | 不做"添加孩子"按钮（那是家长端的活）、不做删除、不做密码找回、不做孩子列表排序设置 |
| 空态 | 家里一个孩子都没有：显示"还没有小朋友，请家长先设置"+「请家长来设置」按钮（点开即家长 PIN） |

**关键设计判断**：头像墙是唯一的视觉主体，占屏 60% 以上。孩子不需要读文字，靠图片认自己。

### 2.2 P-C2 今日任务（Tab 1）

| 项 | 内容 |
|---|---|
| 页面职责 | 回答"我现在要做什么"，并把做完的任务交出去 |
| 布局结构 | 顶部：问候（「早上好，朵朵」）+ 今日进度（`3/5 做完啦`）→ 分区列表（见下）→ 底部 Tab Bar |
| 分区顺序 | ①**需要改一下**（待修改，有明确动作，置顶）②**要做的**（待完成，含今天的与往期未完成的）③**等爸爸妈妈看**（待家长确认）④**已完成**（已通过，默认折叠） |
| 核心操作 | 任务卡上的主按钮：「我做完啦」（待完成 / 需修改） |
| 次级操作 | 卡片展开看详情（任务说明、星星数） |
| 出口 | ① 切 Tab 到 P-C3 / P-C4 ② 顶部右上角「家长」③ 完成任务后原地留在本页（不跳页） |
| 刻意不做的 | 不做"全部完成"一键提交（每条任务必须单独确认，避免误触）、不做拖拽排序、不做筛选器 |
| 空态 | 今天没有任务且无往期未完成：「今天没有任务，去陪宠物玩吧」+「去找宠物」按钮 → P-C3 |

> ⚠️ **待裁决冲突 G-01（不在本页擅自扩设计）**：`PRD_v1.3.md` §5.3 写明第一版支持三种提交方式——**文字提交、照片提交、家长确认**，且照片原图须存本地数据库。本页自 v0.1 起按"提交 = 点一下（我做完啦）"设计，**没有文字输入框、没有拍照上传**。这是**范围级冲突**，影响本页卡片结构、状态矩阵、数据模型（Blob）与备份文件内容。裁决前：① 不新增附件界面 ② 也不删除本冲突记录 ③ 不把"无附件"写成冻结规则 ④ Trae 不应自行实现拍照上传。详见 `00_设计任务说明.md` §7.2 与 §9.1。
>
> 另有**一个必须由 Owner 定性的问题**：PRD 把"**家长确认**"和文字、照片并列称为"三种提交方式"，但它读起来更像**审核动作的另一种叫法**。本设计的处理是：无论它被定义成"第三种提交方式"还是"审核动作"，**奖励都只能由家长端的审核动作发放**（IR-05）——孩子端不得存在任何"我自己确认一下就到账"的路径。若按"提交方式"理解，它也只是把任务送入"待家长确认"，不缩短链路。

#### 2.2.1 往期未完成的任务放在哪（关键补充）

PRD 规定「逾期任务允许补交」。但如果孩子端只显示当天任务，昨天没做完的任务就会从界面上消失——**孩子找不到它，补交规则等于失效**。因此本页必须承载往期任务：

| 规则 | 内容 |
|---|---|
| 归属分区 | 往期未通过的任务并入 **②「要做的」** 区，不新开分区（孩子端分区不超过 4 个） |
| 排序 | 今天的任务在前；往期任务按应完成日期**由新到旧**排在后面 |
| 数量上限 | 折叠态最多展示 **3 条**往期任务 |
| **折叠提示文案** | 折叠行的固定文案：**`还有 N 条逾期任务，展开查看`**（N 为被折叠的条数，N ≥ 1 时必现）。<br>展开后该行文案变为 **`收起`**。<br>**禁止**只显示 3 条而让其余任务静默消失——被折叠的任务必须通过这句提示保持"可被发现"。 |
| **展开入口位置** | 「要做的」区**底部**，作为该区最后一行（不是标题旁、不浮动、不吸底）。<br>理由：① 区域标题在滚动时会移出视野，把入口放在标题旁等于"滑到下面就看不见入口"；② 孩子线性阅读到区末，"还有…"符合直觉；③ 标题旁空间在窄屏上不足，容易挤压区标题字数。 |
| **展开交互** | 整行可点（高 48px，左对齐灰色文字 + 右侧下/上箭头），点击展开，再次点击（文案已变「收起」）收起。<br>展开/收起为 200ms 高度过渡，不跳页、不弹层。<br>展开状态在**本次会话内按"孩子 + Tab"记忆**：切到宠物页再回来仍保持展开；刷新或冷启动恢复默认折叠。 |
| 视觉标记 | 往期任务带灰色「补交」标签（规格见 `02_页面状态矩阵.md` 第 4 节），**不使用红色、不使用警告图标**；除标签与副标题外，卡片样式、按钮、可点区域与今日任务**完全一致** |
| 时间说明 | 卡片副标题显示「昨天的」/「11月16日的」，仅此一句，不加天数倒计时 |
| **完整流程** | 补交任务与今日任务走**完全相同**的状态机：`待完成 → 提交 → 待家长确认 → 家长审核 → 通过（发放全部原定星星与经验）`。补交不另行简化流程、不缩短审核、不降低奖励。 |
| **折叠不影响数据** | 折叠是**纯展示层的客户端状态**，不得写入任务字段、不得作为任何查询或同步的过滤条件。孩子提交了折叠区里的任务，该任务立刻变为 `submitted`，家长端 P-P3 必须能收到（详见 `03_交互规则.md` IR-31）。 |
| 家长侧对应 | 家长在 P-P1 展开孩子明细时，同样可见往期未完成任务及其「补交」标记；在 P-P3 待确认中心，来自补交的提交带同样的灰色「补交」标签，**且在列表中的位置不受孩子端是否折叠影响**。 |
| 历史数据 | 已通过/已退回的往期任务不因"过期"被清理（K18）。第一版不提供按日期回看的入口（V2-01），但数据完整保留。 |

**为什么并入而不单开一区**：如果给"补交"单独开一个分区，等于在界面上给孩子标出"你欠了 3 件事"。并入「要做的」后，它只是一条稍晚的任务，而不是一份欠账清单。

**为什么上限 3 条，但必须显示折叠提示**：长期不做任务的孩子可能积压十几条，全部铺开会形成压迫感，孩子更不想打开应用。但**折叠 ≠ 隐藏**——如果没有"还有 N 条逾期任务"这一行，被折叠的任务在界面上就等同于不存在，孩子既看不到也想不到，补交规则再次失效。所以折叠的代价必须用一行明确的提示换回来：视觉压力降低，可发现性不降低。

**为什么展开入口放底部而不是标题旁**：这是一次实测视角取舍。孩子端的「要做的」区在有 3 条往期任务时，区高度约 500px，手机上滚动到区中部时标题已经出屏；如果入口在标题旁，孩子滚到区底部反而找不到它。

**为什么"需要改一下"排最前**：它是唯一带"被要求"情绪的分区，压在最下面会让孩子反复滑过却不动手；放在最上并配紫色（非红色）视觉，把它变成"待办"而不是"批评"。

### 2.3 P-C3 宠物与积分（Tab 2）

| 项 | 内容 |
|---|---|
| 页面职责 | 让努力可见，允许孩子发起一次兑换申请，并管理已拥有的宠物装扮 |
| 布局结构 | 上半屏：宠物形象（含已穿戴装扮）+ 等级 + 经验条 + 星星余额（大数字）→ 下半屏：积分奖励中心（`生活奖励` / `宠物装扮` 分类）→「我的宠物装扮」与「我的兑换申请」入口 |
| 核心操作 | 奖励卡上的「我想换这个」；已拥有装扮卡上的「穿戴 / 卸下」 |
| 次级操作 | 查看装扮效果、已拥有 / 已穿戴状态、兑换申请记录（等待确认 / 已换到 / 没换成） |
| 出口 | ① 切 Tab ② 顶部右上角「家长」③ 装扮预览 / 穿戴管理在原页弹层或页内区域完成 |
| 刻意不做的 | 不新增核心页面；不做"再来一次/加速成长"付费或诱导按钮、宠物互动、上传素材、复杂动画；不做库存、限购或真实支付 |
| 空态（奖励） | 两类均无启用奖励：「还没有能换的奖励，可以问问爸爸妈妈」；收藏为空：「还没有装扮，换到后会出现在这里」 |
| 状态提示 | 有 1 条待确认申请时，奖励区顶部显示一行浅色提示：「你申请换 XX，等爸爸妈妈确认」；已拥有装扮不再显示兑换按钮 |

**页内顺序**：宠物与星星始终在上；奖励中心先展示分类，再展示奖励名称、说明、当前积分和申请按钮。「我的宠物装扮」按五类展示已拥有与当前穿戴状态，未拥有项只在奖励中心 / 预览中出现。预览不保存；切换同类别装扮只替换该类别，穿戴状态刷新后保留。

### 2.4 P-C4 连续学习（Tab 3）

| 项 | 内容 |
|---|---|
| 页面职责 | 让孩子感知"坚持"这件事，而不是被数据考核 |
| 布局结构 | 中央大数字「连续 6 天」→ 最近 7 天点阵（今天最右）→ 一句解释文案 |
| 核心操作 | 无主操作（这是纯查看页） |
| 次级操作 | 点击某一天圆点，显示当天通过了哪几条任务（轻量弹层） |
| 出口 | ① 切 Tab ② 顶部右上角「家长」③ 无任务时引导去 P-C2 |
| 刻意不做的 | **不做趋势折线、不做月历、不做百分比、不做与别人比较**。7 天点阵是"打卡痕迹"，不是"数据图表"，两者视觉语言必须不同（圆点无坐标轴、无网格、无刻度） |
| 空态 | 从未有过通过记录：「从今天开始，第一条通过的任务会点亮第一颗星星」（文案指向 P-C2） |

**必须写在页面上的解释**（K17）：当孩子问"我昨天补交的为什么不算昨天"时，家长需要一句现成的话。页面底部常驻小字：「只有爸爸妈妈当天确认通过，这一天才会亮起来。」

### 3.1 P-P1 孩子列表（Tab 1，首页）

| 项 | 内容 |

| 布局结构 | ①**备份提醒条**（有条件显示，见状态矩阵第 7 节）②每个孩子一张概览卡：头像 + 昵称 + 今日进度 `3/5` + 待确认数 + 星星数 ③底部 Tab Bar |
| 核心操作 | 点孩子卡 → 展开该孩子今日任务明细（弹层/展开区，不是新页面） |
| 次级操作 | 卡片上的「去确认」快捷入口 → P-P3（已按该孩子预筛） |
| 出口 | ① 4 个 Tab ② 右上角齿轮 → P-P5 ③ 孩子卡 → 明细 |

### 3.2 P-P2 任务布置与管理（Tab 2）

| 项 | 内容 |
|---|---|
| 页面职责 | 把"每天/每周要做的事"设好，一次性减少每天的重复操作 |
| 布局结构 | 顶部切换：`每日` / `每周` / `临时` → 任务模板列表 → 右下角悬浮「+ 新建任务」 |
| 核心操作 | 「+ 新建任务」→ 表单（任务名、星星数、适用孩子、重复规则） |
| **每周任务的必填项** | 选择「每周」时，**必须指定生成星期，且可多选**（一~日，至少选 1 天才能保存）。未选星期时「保存」禁用并提示「请选择在哪几天生成」。周模板只在所选星期生成当天实例（IR-02）。<br>⚠️ **本规则是设计建议，Q-03 待 Owner 确认**（见 `00` §9）：可照此实现，但星期规则必须集中在一处，便于整体替换。 |
| 次级操作 | 编辑、停用（不删除历史）、调整星星数 |
| 出口 | ① 保存后留在本页 ② Tab 切换 |
| 关键区分 | **每日/每周固定任务** = 模板，每天自动生成一条待完成实例；**临时任务** = 只生成一次，需指定日期 |
| 空态 | 某个分类无任务：「还没有每日任务，加一条每天都要做的吧」 |
| 刻意不做的 | 不做拖拽排序、不做批量导入任务模板、不做任务库/推荐任务 |

**设计要点**：家长最痛的不是"布置一次"，而是"每天重新布置一次"。所以本页的默认视图是"我设过的固定任务"，让家长确认"这些还在生效"，而不是每次都从零开始填。

| 页面职责 | 用最短路径把所有待审核提交处理掉 |

| Tab 角标 | 待确认数 > 0 时 Tab 显示数字角标；= 0 时不显示（不显示 0，避免无意义焦虑） |

### 3.4 P-P4 积分与奖励（Tab 4）

| 项 | 内容 |

| 页面职责 | 让星星的来去可查、可控、可解释 |

### 3.5 P-P5 设置与备份（工具页）

| 项 | 内容 |
|---|---|
| 页面职责 | 数据安全兜底 + 家庭成员的增删改 + 家长 PIN 管理 |
| 布局结构（分组） | **① 家长模式**：修改 PIN、查看/重新生成恢复码<br>**② 孩子管理**：添加/编辑孩子（头像、昵称、孩子 PIN 开关）<br>**③ 存储与备份**：存储状态（是否已持久化）+「申请持久化」、上次导出时间、「导出数据」、「导入数据」<br>**④ 关于**：版本号、更新说明<br>**⑤ 危险操作**（本版新增，**G-05 · D2 待确认**）：删除全部家庭数据 |
| 核心操作 | 导出数据（蓝色主按钮）、导入数据（描边按钮，危险动作需二次确认） |
| 次级操作 | 修改 PIN、管理孩子 |
| 出口 | 返回上一页（齿轮入口 → 返回 P-P1） |
| 刻意不做的 | 不做账号、不做云同步开关、不做主题切换、不做通知设置（无此功能） |
| **危险操作组位置** | 页面**最底部**，「关于」之后，与上方分组之间留 24px 分隔 + 一条浅灰分割线。<br>**理由**：① 这是全站唯一不可逆操作，不能排在「导出」附近（家长快速下滑时容易误触）；② 但也必须**能找到**——不能藏进三级菜单，PRD §11.6 明确要求支持；③ 放在最底部符合"破坏性操作在末尾"的通用预期。<br>**视觉**：文字按钮（非实心按钮），灰色文字 + 红色仅用于**删除确认弹层内的最终按钮**（家长端允许红色；孩子端仍然全站禁红）。 |
| **语义区分（必须写清）** | 本页的「删除全部家庭数据」与 `02` §8.3 的**异常页禁止"清空重来"**不矛盾，两者语义相反：<br>· 本页入口 = **家长在正常状态下主动**清理，有 PIN 与二次确认，是他知情的选择；<br>· 异常页 = **系统在故障时**不得引导用户销毁可能是唯一数据副本的东西。<br>因此**异常页永远不出现"删除/清空"按钮**，即使 P-P5 有该入口。 |

**关键设计判断**：导出按钮必须是本页**视觉最重**的元素。这是"无后端"方案下唯一的数据保险，它不能在视觉上弱于"修改 PIN"。

### 3.6 删除全部家庭数据的流程层级（P-P5 的子流程，**不新增页面**）

> 状态：**G-05 · D2 待确认**（方案完整，Owner 未裁决前不得当成冻结规则宣传，但可按此实现）
> 依据：`PRD_v1.3.md` §11.6。归属：P-P5 的一个分区 + 两个覆盖层，**页面清单仍是 9 页**。

```
P-P5（设置与备份）
  └─ ⑤ 危险操作：「删除全部家庭数据」（文字按钮）
        │ 点击
        ▼
  ① PIN 重验层（全屏弹层，4 位数字键盘）
        │ 正确
        ▼
  ② 删除范围说明层（全屏弹层，不可下滑关闭）
        │ 勾选 + 点「永久删除」
        ▼
  ③ 执行中（全屏，不可交互）
        │
   ┌────┴─────┐
   ▼          ▼
 成功        失败
   │          │
   ▼          ▼
重新加载   回到 ② 说明层 + 失败原因 + 「再试一次」/「取消」
   │
   ▼
P-C1 空家庭态 →「请家长来设置」→ 家长 PIN 设置 → 添加孩子
```

| 层 | 页面职责 | 必须包含 | 出口 |
|---|---|---|---|
| ⑤ 入口 | 让家长能找到，但不会误触 | 分组标题「危险操作」+ 一行说明「删除后无法恢复」 | 点击进入 ① |
| ① PIN 重验 | 确认操作人**此刻**是家长（不依赖已登录的会话） | 「请输入家长 PIN」+ 4 位键盘 + 「用恢复码」兜底 | 正确 → ②；取消 → 回 P-P5；连续 5 次错误 → 提示用恢复码 |
| ② 范围说明 | 让家长知道**删什么、不删什么** | 见下方"范围说明必备四条" | 「永久删除」（危险色，需勾选后可用）/「取消」 |
| ③ 执行中 | 不可交互，防重复 | 「正在删除…」 | 自动转成功/失败 |
| 成功 | 明确结束，不留悬念 | 「已经删除了」+ 一句「现在可以从头开始设置」 | 重新加载 → P-C1 空家庭 |
| 失败 | 不能假装成功 | 「这次没删干净」+ 原因 + 「再试一次」 | 重试 / 取消（**取消后必须说明当前数据状态**） |

**② 范围说明必备四条**（缺一条就是隐瞒后果）：

1. **会删除**：所有孩子的资料、任务与任务模板、审核记录、星星流水、宠物等级与经验、连续学习记录、奖励设置、家长 PIN 与恢复码。→ 删除后本机**没有**任何家庭数据。
2. **不会删除**：你自己保存到手机/电脑上的备份文件（应用碰不到这些文件）。
3. **可以恢复吗**：只有你自己保存过备份文件才能恢复；没有备份就**无法找回**。
4. **这不是"恢复备份"**：删除和恢复是两个独立操作，删除后要恢复，需要另外走一次"从备份恢复"。

### 4.3 强制约束

- **孩子端 → 家长端**：唯一路径是右上角「家长」+ PIN。
- **家长端 → 孩子端**：唯一路径是 P-P5 或 P-P1 中的「退出家长模式」→ 回 P-C1。
- **不存在直接跳转**：任何页面不得出现"切换到孩子视角预览"的入口。
- **删除全部数据（G-05）必须二次验证 PIN**：即使当前已在家长模式，进入 §3.6 的①仍要重新输入 PIN。理由：家长模式可能被孩子趁家长离开时接管（K5/PIN 只是误触屏障），而删除不可逆，必须再确认一次操作人。**不得**用"已在家长模式"跳过这一步。
- **无深链接要求**：PWA 不做 URL 直达敏感页（家长页不得由 URL 直接打开而绕过 PIN；删除确认层不得由 URL 直达）。

### 4.4 异常与恢复路径（全局兜底层，不计入 9 页）

数据库异常时，业务页面**全部不可达**，此时只有一条路径：异常页 → 恢复流程 → 重载。因此它不参与上面的页面层级，但必须定义清楚：

| 起点 | 触发 | 终点 | 备注 |
|---|---|---|---|
| 任意页 | 数据库打不开（I3/I4） | **全屏数据异常页** | 渲染时不显示 Tab Bar，任何业务页都进不去 |
| 异常页 | 点「重新打开」 | 重新加载应用 | 可能仍打不开（属正常，不做无限重试引导） |
| 异常页 | 点「从备份恢复」 | 恢复流程（选文件 → 校验 → 确认 → 重建 → 写入 → 校验） | **不依赖原数据库**；规格见 `02` §8.6 |
| 恢复流程 | 校验通过 + 家长确认 | 重建并写入 | 家长不确认则回异常页 |
| 恢复流程 | 重建目标库失败 | **终止态页** | 不提供重试；建议换浏览器/设备（§8.6.5） |
| 恢复流程 | 成功 | 重新加载 → 家长端 P-P1（或 P-C1） | 首次进入提示一次"已从 X 日的备份恢复" |
| 业务页 | 单表读取失败（I2） | **停留本页**，区块级错误卡 | 不清空界面、不跳异常页（IR-40） |

**两条必须记住的结构事实**：
1. 异常页与终止态页**不是第 10、11 个业务页面**，它们是兜底层；页面清单仍是 9 页。
2. 恢复成功后**不新增页面**，回到正常业务界面。

**一条必须分清的分界（v0.4 补）**：**"删除全部家庭数据"不属于本节的兜底层。** 它是 P-P5 里的一个正常业务入口（§3.6），只在数据库**可用**时出现；数据库打不开时，异常页与终止态页**都不提供删除/清空**（否则等于在故障时引导用户销毁唯一的数据副本）。两条路径的落点也不同：删除成功 → 空家庭初始化；恢复成功 → 有数据的业务界面。

### 7.1 入口放在哪（一张表看清）

| 能力 | 家长端入口 | 孩子端入口 | 是否新增页面 |
|---|---|---|---|
| 改昵称 | P-P5 孩子管理 → 孩子行「编辑资料」；P-P1 孩子卡长按/编辑图标 | P-C3 宠物区下方「我的资料」→ 改名字 | 否，覆盖层 |
| 改头像 | 同上「编辑资料」→ 点头像 | P-C3「我的资料」→ 点头像 | 否，覆盖层 |
| 换宠物 | —（家长不替孩子选，避免"被安排"） | P-C3 宠物区右上「换个伙伴」 | 否，页内覆盖层 |
| 改奖励积分 | P-P4 奖励管理 →「改积分」 | ❌ 不出现 | 否，原有弹层内改交互 |

**家长端为什么不提供换宠物**：宠物是孩子自己的伙伴，家长代选会削弱归属感；家长已有的权力（定价、审核、启停）足够。若 Owner 要求家长也能改，只需在「编辑资料」里加一行「伙伴：小猫 · 换一个」，不新增结构。

### 7.2 权限矩阵（唯一口径）

| 操作 | 家长 | 孩子（自己） | 孩子（别人） |
|---|---|---|---|
| 改昵称 | ✅ 所有孩子 | ✅ 仅自己 | ❌ 看不到入口 |
| 改头像 | ✅ 所有孩子 | ✅ 仅自己 | ❌ |
| 恢复默认头像 | ✅ | ✅ | ❌ |
| 换宠物 | ❌（本版） | ✅ 仅自己 | ❌ |
| 改奖励积分 | ✅ | ❌ | ❌ |

- **孩子改自己的资料不需要家长 PIN**：PIN 保护的是"审核、定价、删除、导入"这类影响钱与不可逆数据的动作；改名字和头像不改变任何学习记录，加 PIN 只会让孩子放弃个性化。
- 孩子端不出现"选择孩子"的控件，因此不存在"改到别人"的路径；服务层仍需按 `childId` 校验（IR-13）。

### 7.3 覆盖层清单（都不进浏览器历史，返回键关闭）

| 编号 | 名称 | 触发 | 关闭方式 |
|---|---|---|---|
| O-6 | 编辑孩子资料（昵称 + 头像） | 家长端孩子行 / 孩子端「我的资料」 | 取消 / 保存后自动关 |
| O-7 | 头像来源选择 | O-6 点头像 | 取消 / 选择后进入裁剪或直接生效 |
| O-8 | 头像裁剪 | 选完本地图片 | 取消（不改变原头像）/「就用这张」 |
| O-9 | 选择伙伴 | P-C3「换个伙伴」 | 返回 / 确认后关闭并刷新宠物区 |

> O-6 在**家长端是底部弹层**（家长端已有大量弹层习惯），在**孩子端是页内展开区**（孩子端不用底部弹层改资料，避免键盘遮挡与"找不到保存"）。同一个能力，两端口径不同是有意的。

### 7.4 与现有 IA 的关系

- P-C1 身份选择的头像墙**只读**：不在入口页提供编辑，避免孩子一进来就改资料而不做任务；
- P-P1 孩子卡上的头像与昵称是**派生显示**，改完立即在所有页面同步（不允许缓存旧昵称）；
- P-P5 的「孩子管理」分组不新增区块，只在每个孩子行末尾增加「编辑资料」文字按钮；
- P-C3 新增一行「我的资料」入口，位置在「我的宠物装扮」之后，不挤占奖励中心。

### 7.5 刻意不做（D3）

- 不做孩子资料页（独立路由）——资料只有 3 个字段，开页太重；
- 不做头像相册、多图轮播、贴纸；
- 不做"孩子之间互看资料"；
- 不做家长代选宠物（见 7.1 说明，可按 Owner 意见后加）。
