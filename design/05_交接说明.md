### 2.2 状态枚举（语义已定，字面值你定）

### 2.3 字段语义依赖（**仅语义，表结构与命名由你定**）

以下是界面渲染所依赖的最小字段集合。凡标注"派生"的，建议计算而非存储。

**孩子**
`id` / `昵称` / `头像标识`（固定集合中的一项，非上传文件） / `是否设孩子PIN` / `孩子PIN值`

**任务实例**
`id` / `所属孩子` / `任务名` / `星星数` / `类型`（daily/weekly/temp） / `状态` / **`应完成日期`（`dueDate`，**日期级**：`YYYY-MM-DD` 或本地零点的日期对象，**不是时间戳、不是日期时间**，Q-14）** / `提交时间` / `审核时间` / `退回原因` / `是否补交`（**派生**：应完成日期 < 今天 且 未通过） / `来源模板id`（固定任务需要，用于幂等）

> **`dueDate` 的三条硬约束（Q-14 已确认）**：① 语义是"哪一天"，不是"哪一刻"；② 逾期判定一律 `dueDate < 今天(本地自然日)`；③ 不要为了"以后可能要做小时级"而先存成时间戳——那会让"今天"的判定出现时区与时刻边界问题。若要存时间戳，必须另加一个"业务日期"字段承担判定，**不允许**直接用时间戳判断逾期。

**附件（照片 / 文字提交备注）—— ⚠️ 条件规格，`G-01` 未裁决前不建**

`PRD_v1.3.md` §5.3 要求支持文字提交与照片提交，Owner 尚未裁决（`00` §9.1）。因此本节**只写"若裁决包含"时的语义要求，不要求你现在建表**：

| 若裁决包含 | 语义要求（命名与表结构仍由你定） |
|---|---|
| 文字提交 | 任务实例上需要一个**可空的提交说明**字段（纯文本，长度上限你定）；提交后随任务锁定（IR-04），孩子不能改 |
| 照片提交 | 需要一个与任务关联的**二进制存储**（独立表或任务上的 Blob 列），存**原图本体**，不得只存 `blob:` URL / objectURL（重开应用即失效，IR-17） |
| 共同要求 | ① 附件只影响"提交内容"，**不影响奖励发放**（仍须家长审核，IR-05）② 导出必须带实际二进制（IR-17）③ 备份恢复按 IR-37 第 7 条校验④ 删除任务/孩子/全部数据时，附件必须一并删除，不留孤儿 Blob |
| **裁决前你必须做的** | ① 不要建 Blob 表 ② 不要把"任务记录很小"写进任何容量假设或性能优化 ③ **备份格式必须带版本字段**——这样将来加表不算破坏兼容（这条无论 G-01 怎么裁决都要做） |

**任务模板**
`id` / `任务名` / `星星数` / `类型` / `适用孩子集合` / **`生成星期`（weekly 必填，**多值集合**，如 [1,3,5]；Q-03 **待 Owner 确认**）** / `是否启用`

> **注意**：任务实例上**没有、也不应该有**"是否允许补交"字段——补交是全局规则（Q-04），不是任务属性。任何"给某任务关掉补交"的需求，第一版不支持。

**积分流水**
`id` / `所属孩子` / `变动值`（正负整数） / `事由文案` / `来源` / `关联任务id`（可空） / `关联兑换id`（兑换时必填） / `事件唯一键`（兑换建议 `redemption:${redemptionId}`） / `时间`

> 星星余额 = 该孩子全部流水变动值之和（**派生，不要单独存一个可写的 balance 字段**，否则会与流水不一致）。
> 流水**不做时间裁剪、不做归档删除**（K18）。分页读取，不设"只保留 N 天"。

**宠物**
`所属孩子` / `等级` / `当前经验` / `升级所需经验`（可派生自等级）

> 经验与星星**分开记账**（K11 **已确认**：两次写入、两处存储）：**不要**让经验由星星求和派生，**也不要**用同一个字段承载两者。<br>
> **1:1 是设计建议，Q-05 待 Owner 确认**：实现时把系数抽成常量（如 `EXP_PER_POINT = 1`），不要在业务判断里出现字面量 1，也不要在界面上承诺"1 颗星星 = 1 点经验"。若 Q-05 改为其他系数或按任务类型区分，只改常量/加字段，不动表结构主体。

**连续学习**
`所属孩子` / `当前连续天数`（**派生**，判定口径见 IR-20：`lastPass` 为今天或昨天则保留，≤ 前天则归零） / 通过日期集合

> 通过日期集合**只能追加、不可篡改**。补交通过写入"今天"，**不得**回填原定日期。

**奖励（家庭当前配置）**
`id` / `来源`（builtin / custom） / `templateKey`（内置必填且稳定） / `类别`（life / costume） / `名称` / `说明` / `iconKey` / `defaultCost`（内置建议价） / `cost`（家庭当前价） / `是否启用` / `costumeKey`（装扮必填） / `创建时间` / `更新时间`

> 系统模板目录另保存不可变的模板标识、建议价和素材定义；首次启用 / 初始化才复制到家庭配置。Seed / 刷新只补缺失，不覆盖已有 `cost`、启停或家长内容。自定义奖励只建生活奖励，必须显式设置 `cost`，不继承 defaultCost。
>
> **无库存、无限兑（Q-13 已确认）**：不要加 `stock` / `quantity` / `remaining` / `maxPerChild` 之类字段，也不要做库存扣减、库存恢复、"库存不足"分支。兑换唯一数值校验是**星星余额 ≥ 申请快照价格**。装扮收藏唯一不是库存。

**兑换申请**
`id` / `所属孩子` / `奖励id` / `状态` / `申请时间` / `处理时间` / `家长留言`（可空，≤30 字） / `rewardNameSnapshot` / `costSnapshot` / `categorySnapshot` / `costumeKeySnapshot`（装扮必填） / `assetKeySnapshot`（装扮必填）

> 快照在申请时写入且之后不可改；审核金额只取 costSnapshot。状态仅 pending / accepted / rejected，每孩同时最多一条 pending。

**系统装扮定义（建议代码目录，不是孩子收藏）**
`costumeKey` / `slot`（hat / glasses / scarf / outfit / background） / `名称` / `assetKey` / `建议默认积分`

**孩子装扮收藏（后续新增）**
`id` / `childId` / `costumeKey` / `sourceRedemptionId` / `acquiredAt`；同一 `(childId, costumeKey)` 唯一，sourceRedemptionId 唯一。

**孩子当前穿戴（后续新增）**
`childId` / 各 slot 当前 costumeKey（未穿戴则省略该属性） / `updatedAt`。写入前必须验证对应收藏属于同一 childId；预览不写此记录，穿戴 / 卸下不写积分或经验流水。

**全局设置**
`家长PIN` / `恢复码` / `上次导出时间` / `存储持久化状态`

### 2.4 查询模式（供你建索引参考，非强制）

### 3.2 P-C2 今日任务

| 项 | 内容 |
|---|---|
| 路由 | `/child/:childId/today` |
| 数据依赖 | **今天的任务 + 往期未通过的任务**（名、星星、状态、是否补交、应完成日期、退回原因）、今日进度（今天已通过数 / 今天应做总数） |
| 关键事件 | `child.task.submit` → 按钮禁用 → 成功后原地改态；展开卡片看详情；切 Tab |
| 分区渲染顺序 | **需修改 → 要做的（今天在前、往期在后，往期带「补交」标签，最多 3 条其余折叠）→ 等爸爸妈妈看 → 已完成（默认折叠）**；空分区整块隐藏 |
| **折叠交互（R1 补充）** | ① 位置：「要做的」区**底部最后一行**，整行可点，高 48px ② 折叠态文案固定为 `还有 N 条逾期任务，展开查看`（N ≥ 1 必现）③ 展开后文案变 `收起`，再次点击收起 ④ 展开/收起 200ms 高度过渡，不跳页不弹层 ⑤ 状态只存内存/会话（childrenId + tab 为键），刷新恢复折叠 |
| **折叠的实现约束** | 折叠是**展示层切片**，不是数据过滤：先按查询取全部往期任务，再在渲染层切前 3 条 + 折叠行。**不要**在数据库查询里加 `limit(3)`（否则 N 算不出来，且容易连带把后续提交的查询也限住）。**不要**把折叠写进任何字段（IR-31）。 |
| 必须实现 | ① 四状态卡片视觉差异（04 文档 7.1）② `submitted` 完全只读（IR-04）③ 进度文案 `3/5 做完啦`（分母只算今天的应做数）④ 全部完成的庆祝态 ⑤ 空态按钮跳 P-C3 ⑥ **往期未完成任务必须在「要做的」区承载**（否则补交入口不存在）⑦ 折叠提示行不得静默消失 |
| 边界 | 单条任务数据异常时只降级该卡（02 文档 2.2 部分异常），不让整页崩；折叠区内的异常卡同样只降级自己 |
| 由你决定 | 折叠区的展开方式（手风琴 / 按钮）、卡片是否需要进入详情页（**建议不要，卡片内展开即可**） |

### 3.10 数据库异常恢复（原库不可用时的重建路径）

这是本版新增的交接内容。**设计侧只给行为规格，具体技术实现由你提方案并在 Review 中说明。**

**场景**：数据库打不开（I1/I3/I4），常规导入无法执行，因为常规导入依赖一个可用的库。

| 步 | 行为要求 | 实现约束（设计侧的硬要求） |
|---|---|---|
| 1 选文件 | 无库状态下也能打开文件选择器 | 不得把"库已就绪"作为选文件的前置条件 |
| 2 读取与校验 | 在**数据库之外**（临时内存/临时存储）完成读取与全部校验，并做**大小与空间预检** | 此阶段**不得**创建、清空、迁移任何业务库；校验项见 `03` IR-35 七项 + 前置预检表。预检只给风险提示，**不得**自动阻止继续 |
| 3 摘要 + 确认 | 展示备份时间、版本、数据量（**含每张表条数与备份体积**）、可能的空间风险；明确"会重建本地数据库"；需二次点击 | 未确认前不得有任何破坏性动作；确认按钮点后立即禁用（防双写） |
| 4 重建目标库 | 重建失败即终止 | **重建失败不进第 5 步**，直接进终止态（`02` §8.6.5） |
| 5 写入 | 全部数据必须在**一个事务**内写入 | 若运行环境无法单事务：失败后必须清除本次写入的部分数据，回到"无可用库"，不得留下半成品 |
| 6 校验 | 按 `02` §8.6.3 / `03` IR-37 的 **7 条**判据核对 | 分表条数、关键关联、积分汇总、宠物经验、附件可读（依赖 G-01）逐项做；**不得只判"事务没报错"，不得只比总记录数** |
| 7 元数据 | 写"上次恢复时间" | **不得**把"上次导出时间"改成现在（否则备份提醒被错误清零） |
| 8 重载 | 成功后重新加载应用 | 重载后不得再弹"是否导入" |
| 9 收尾 | 首次进入提示一次「已从 X 月 X 日的备份恢复」 | 只提示一次 |

**不得做的事（设计红线）**：
- ❌ 因"数据库打不开"而显示"无法恢复"并只给一个"重新打开"按钮。
- ❌ 用"新建一个空库 + 提示恢复成功"冒充恢复。
- ❌ 校验未通过就重建；家长未确认就重建。
- ❌ 恢复过程中删除、移动、改名用户选择的备份文件。
- ❌ 恢复失败后显示"部分成功"或"稍后会自动补全"。
- ❌ 在某一步失败后自动重试重建（环境类失败重试无意义）。
- ❌ 把"空间估算"写成"空间够用，可以放心恢复"（估算≠承诺，见 `03` IR-35 前置表）。
- ❌ 写入失败后留下一个能被正常业务界面打开的残缺库（见下方"半成品判定"）。

**半成品库的判定与处理（v0.4 新增，必须实现）**：
写入失败后若目标库仍然存在且含部分数据，**必须在重载后识别为"恢复未完成"并拦在 F2 界面**（例如依赖"写入完成标记"这类显式状态），**禁止**让它直接进入业务界面。设计侧的底线只有一句：**家长永远不应该看到一个"看起来正常但少了一半数据"的家庭**。

**附件（照片 Blob）的条件规格（G-01 未裁决）**：
若 Owner 裁决第一版含照片提交，则恢复流程必须额外满足 `03` IR-37 第 7 条（数量 + 总字节 + 抽样可解码）。**在裁决前**：不建 Blob 表、不做 Blob 校验、也不把"无附件"写进导出格式的不可变假设里（备份格式要有版本字段，将来加表不算破坏兼容）。

**终止态与"永久权利"的边界（v0.4 明确）**：
F3 终止的是**本次流程**，不是用户的恢复权利。不要写"数据已丢失/永久无法恢复"；正确表述是"你的备份文件还在，换环境可再试"。同时**不要**在终止页放"我已修复，立即重试"按钮——同环境点它只会再失败一次。

**属于你的技术方案选择（设计侧不指定）**：
"用**临时恢复库**写入再安全切换"还是"清空原库后就地写入再校验"，以及是否采用**可回滚**策略（备份原库 → 写入新库 → 切换 → 保留旧库一段时间），**由你提方案并在 Review 中说明取舍**。设计侧只要求结果满足 IR-37 七条且不留半成品，不指定实现架构（见 §4 第 17 条）。

**需要你补充方案的技术点**（见 §4 第 13–16 条）：临时校验数据的存放形式与生命周期、重建目标库时的命名/版本策略（旧库是"删除"还是"改名隔离"）、单事务写 Blob 的可行性与替代方案、校验阶段如何避免把大文件整个读进内存（大备份的分块校验）。

### 3.11 恢复流程的界面状态机（供你实现时对照）

| 状态 | 触发 | 界面 | 允许的用户动作 | 数据现状 |
|---|---|---|---|---|
| `abnormal` | I1/I3/I4 | 全屏数据异常页 | 重新打开 / 从备份恢复 / 关掉其他标签页 | 未知但不删 |
| `picking` | 点「从备份恢复」 | 系统文件选择器 | 选文件 / 取消 | 不变 |
| `validating` | 已选文件 | 全屏「正在检查备份文件…」 | 无（不可交互） | 不变 |
| `confirm` | 校验通过 | 弹层：摘要 + 风险句 + 二次确认 | 取消 / 重建并恢复 | 不变 |
| `rebuilding` | 已确认 | 全屏「正在准备本地空间…」 | 无 | 旧库可能被清理，**新库尚未建立** |
| `writing` | 重建成功 | 全屏分区进度「正在恢复数据（3/7）」 | 无 | 写入中（未提交） |
| `verifying` | 写入完成 | 全屏「正在核对…」 | 无 | 已提交，待判定 |
| `success` | **7 条**判据全过 | 「恢复好了」+ 摘要 | 自动重载 | 完整 |
| `failed_file`（F1） | 校验不过 | 弹层 + 具体原因 | 换一个文件 / 取消 | 不变 |
| `failed_restore`（F2） | 写入/校验失败 | 全屏「这次没恢复成功」+「本机现在没有可用的数据」 | 再试一次 / 导出诊断 | 无可用库 |
| `terminal`（F3） | 重建失败 | 终止态页 | 复制诊断信息 / 看常见原因 | 无库；备份文件完好 |

**状态机约束**：`rebuilding` 一旦开始，**不允许回到 `abnormal` 后假装什么都没发生**；若中途失败，必须落到 `terminal` 或 `failed_restore`，并在文案里说明"本机现在没有可用的数据"。

**终止态不是终态**：`terminal` 是**本次会话的终点**。用户修复环境后重新打开应用，会重新从 `abnormal`（若库仍打不开）或正常界面开始。**不要**把它实现成"写入某个永久失败标记"。

**删除流程的状态机（G-05，与上面这条链完全独立）**

| 状态 | 触发 | 界面 | 允许动作 | 数据现状 |
|---|---|---|---|---|
| `del_idle` | 停在 P-P5 | 底部「危险操作」分组 | 点入口 / 留在本页 | 完整 |
| `del_pin` | 点了入口 | 全屏 PIN 重验层 | 输入 / 取消 / 用恢复码 | 完整 |
| `del_confirm` | PIN 通过 | 范围说明层 + 勾选 | 勾选 → 永久删除 / 取消 | 完整 |
| `deleting` | 已确认 | 全屏「正在删除…」 | 无 | 清空中 |
| `deleted` | 清空成功且重开校验为空 | 「已经删除了」 | 自动重载 | **空** |
| `del_failed` | 事务失败 / 部分完成 | 「这次没删干净」+ 当前数据状态 | 再试一次 / 取消 | 全回滚 / 部分删除（须标注不完整）/ 读不出（转异常页） |

**两条硬约束**：① `deleting` 期间不可返回、不可交互；② `del_failed` 之后**不得**自动重试，也不得把中间态渲染成正常家庭。

| 路由 | 复用 `/parent/settings`，不新增路由；两层确认都是覆盖层（`01` §3.6） |
| 事件 | `parent.data.deleteAll.requested`（点入口）→ `parent.data.deleteAll.confirmed`（勾选后点永久删除）→ `parent.data.deleteAll.done` / `.failed` |
| PIN 重验 | **必须独立校验一次**，不得复用当前会话的"已进入家长模式"状态；校验通过后只对本次删除有效，删除完成或取消即失效 |
| 幂等 | 确认按钮点击后立即禁用直到流程结束；重复点击不得触发第二次清空 |
| 清空范围 | 全部业务表 + 家长 PIN/恢复码 + 家庭设置 + （若含附件）Blob。**逐表清空必须在单事务内**，或采用你评审后认为等价的安全方案（见 §4 第 17 条） |
| 成功判定 | ①事务提交无异常 ②清空后重开库校验为**空** ③不做任何自动生成（不生成今天的任务、不残留 settings）。三条全过才显示「已经删除了」 |
| 失败处理 | 三档：全回滚 / 部分删除（**必须标注不完整**）/ 读不出（转 `02` §8.3 异常页）。**任何一档都不得显示成功**，也不自动重试 |
| 删除后 | 重载 → P-C1 空家庭（「还没有小朋友，请家长先设置」）→ 家长首次设置 PIN。**不弹**"是否从备份恢复" |
| 不做 | ❌ 不动用户设备上的备份文件（应用无权访问）❌ 不注销 Service Worker / 不卸载应用 ❌ 不与恢复流程合并成一个按钮（IR-41 末条） |
| 与异常页的关系 | 异常页 / 终止态页**永远没有**这个入口。异常时放它 = 引导家长销毁可能是唯一副本的数据 |
