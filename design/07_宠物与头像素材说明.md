## 1. 一句话

五种宠物**共用一副骨架**，只换耳朵、尾巴、配色与口鼻；因此现有五件装扮（帽 / 眼镜 / 围巾 / 衣服 / 星空背景）**零适配**直接可用。头像上传与「系统预设头像」是两个并存来源，不是替换关系。

## 3. 五种宠物与共用骨相

### 3.1 为什么共用骨相

现有装扮是把图形**直接画在 264×254 坐标系里**（帽子跟着头晃、围巾贴着脖子）。如果五种宠物各画一套比例，五件装扮就要做 25 次对齐，且以后每加一件装扮都要乘 5。

所以本轮把「可装扮部位」固定成一套几何锚点，宠物之间的差异全部放在**不参与装扮**的部位（耳、尾、配色、口鼻细节）。这是一次性成本换长期可维护性，不是偷懒。

### 3.2 锚点表（五种宠物完全一致，Trae 可直接当常量用）

| 锚点 | 坐标 / 尺寸 | 用于 |
|---|---|---|
| 画布 | `viewBox="0 0 264 254"` | 全部素材与装扮图层 |
| 头 | 中心 `(132,104)`，`rx 65` / `ry 57` | 帽子、眼镜定位基准 |
| 身体 | 中心 `(132,180)`，`rx 63` / `ry 53` | 衣服、围巾定位基准 |
| 眼 | 左 `(108,106)`、右 `(156,106)`，`rx 10.5` / `ry 12.5` | 眼镜片必须对准这两点 |
| 帽檐 | 水平 `y=56`，跨度 `132±82` | 帽子压在头顶 |
| 脖子（围巾） | `y 141–173`，宽 `132±43` | 围巾不遮嘴 |
| 躯干（衣服） | `y 145–212` | 背心、领口 |
| 背景 | `x=8,y=8`，`248×238`，`rx 34` | 星空背景 |
| 影子 | `(132,236)`，`rx 68` / `ry 11` | 落地感 |

### 3.3 五只的形象差异（只在这四处变）

| 宠物 | 主色 | 耳朵 | 尾巴 | 口鼻 / 识别点 |
|---|---|---|---|---|
| 小熊 bear | `#D9A06B` 暖棕 | 圆耳 `r22`，内耳浅棕 | 短圆尾 `r13` | 大块米色口鼻 + 黑豆鼻 |
| 小兔 rabbit | `#F7F1EA` 奶白 | 长耳 `rx17/ry48`，内耳粉 | 圆球尾 `r15` | 三瓣嘴 + 两颗门牙 |
| 小猫 cat | `#F9B268` 蜜橘 | 尖三角耳 | 长弯尾（双描边） | 三角粉鼻 + 胡须 |
| 小狗 dog | `#E9B978` 黄褐 | 垂耳 `rx19/ry33`，画在头之后 | 上翘短尾 | 大黑鼻头 + 粉舌头 |
| 小狐狸 fox | `#F4914F` 橘红 | 大三角耳 + 深色耳尖 | 蓬松大尾 + 白尾尖 | 白口鼻 + 上挑眼线 |

**描边统一**：头 / 身体 `7px`，细节 `3~4.5px`，圆头圆角。这是五只看起来"同一套手绘"的关键，比配色更重要。

## 4. 文件与图层

```
design/assets/pets/
├── cat.svg            小猫（= 现有线上形象，可直接替换渲染层）
├── bear.svg           小熊
├── rabbit.svg         小兔
├── dog.svg            小狗
├── fox.svg            小狐狸
└── compat-check.png   五宠 × 全套装扮的兼容性验证图（本轮实测产出）
```

每个 SVG 内部用 `data-layer` 标注图层，Trae 可以整段搬进现有 `catSvg()` 的渲染函数：

| `data-layer` | 内容 | 是否可被装扮替换 |
|---|---|---|
| `background` | 空容器 | 由星空背景填充 |
| `shadow` | 落地影子 | 否 |
| `tail` | 尾巴 | 否 |
| `body` | 躯干 + 肚皮 + 脚 | 否 |
| `outfit` | 空容器 | 由背心填充 |
| `ear-left` / `ear-right` | 耳朵（画在头之前，耳根被头压住） | 否 |
| `head` | 头型 + `face` 子层 | 否 |
| `face` | 腮红 / 双眼 / 口鼻（`eye-left` / `eye-right` 单独标） | 否 |
| `ear-front` | 垂耳专用（狗用；其他宠物留空） | 否 |
| `scarf` / `glasses` / `hat` | 空容器 | 由对应装扮填充 |
| `spark` | 周围小星星 | 否，可整体关闭 |

> **渲染顺序不能改**：`background → shadow → tail → body → outfit → ear → head → ear-front → scarf → glasses → hat → spark`。改动顺序会让帽子被头挡住、或垂耳盖住镜片。

## 5. 装扮兼容性

### 5.1 结论（已实测）

用现有五件装扮的原始路径直接注入五个 SVG，未做任何单宠适配，产出 `compat-check.png`：

| 装扮 | 熊 | 兔 | 猫 | 狗 | 狐 | 备注 |
|---|---|---|---|---|---|---|
| 草帽 `hat_straw` | ✅ | ✅ | ✅ | ✅ | ✅ | 兔的长耳会被帽檐压住中段，耳尖露出——视为"戴帽子压耳朵"，不做穿模修正 |
| 圆眼镜 `glasses_round` | ✅ | ✅ | ✅ | ✅ | ✅ | 镜片对准同一眼位，五只都正 |
| 针织围巾 `scarf_knit` | ✅ | ✅ | ✅ | ✅ | ✅ | 不遮嘴 |
| 小背心 `outfit_vest` | ✅ | ✅ | ✅ | ✅ | ✅ | 领口在脖子下方，不压下巴 |
| 星空背景 `bg_starry` | ✅ | ✅ | ✅ | ✅ | ✅ | 纯背景层，与物种无关 |

### 5.2 万一将来出现不适配

新装扮（例如"耳朵套""尾巴结"）如果只对某几种宠物有意义，**不要**悄悄错位，按下面三选一：

1. **收窄适用范围**：卡片上标注「适合小猫 / 小兔」，不适用时按钮为「这个戴不上」，不给穿戴入口；
2. **加适配层**：为该宠物补一个 `data-layer="<slot>-<pet>"` 图层，仅在对应物种渲染；
3. **改设计**：把该装扮改成不依赖物种形状（如胸针、围巾、背景）。

禁止的做法：让图层错位、让孩子穿戴后出现"帽子悬空"或"眼镜飘在脸颊"。

## 6. 等级形态怎么处理（本轮的控制点）

`04` §8 原写"7~9 个等级形态"。若照此对 5 种宠物各画 7 级，是 35 套图，且装扮要逐套对齐——**本轮明确不做**（D2，Owner 已允许"先做静态形象"）。

本轮的等级表达改为三层，全部不需要新素材：

| 层级 | 做法 | 成本 |
|---|---|---|
| 尺寸 | `Lv.1–2` 0.92×、`Lv.3–5` 1.0×、`Lv.6+` 1.06×（`transform: scale()`，锚点在脚底） | 0 素材 |
| 徽章 | 右下角 `Lv.N` 圆徽（`04` §8 原有规格） | 已有 |
| 里程碑点缀 | `Lv.5` 加一枚星星胸针、`Lv.8` 加一圈光环（可选，P2） | 2 个小图 |

**明确不承诺**："升级会变成大宠物/新物种"。孩子端文案只说「越来越熟」，与现有措辞一致。

## 7. 头像规格

### 7.1 两种来源并存

| 来源 | 数据 | 显示 | 切换 |
|---|---|---|---|
| 系统预设 | `avatarKey`（8 个 key 之一） | Emoji（现有 `AVATARS`） | 点预设即选中 |
| 自己上传 | 图片（建议 dataURL，见 §7.5） | 圆形裁切显示 | 选图 → 裁剪 → 确认 |

**两条不变量**：
1. 上传头像时**不删除** `avatarKey`，它作为"恢复默认"的落点；
2. 恢复默认时**删除**已上传图片并把 `avatarKey` 置为当前选中的预设——这是唯一会丢弃图片的操作，必须在界面上说清（"删掉自己的照片，用回小动物"）。

### 7.2 处理规格（D2）

| 项 | 规格 | 理由 |
|---|---|---|
| 支持格式 | JPG / JPEG / PNG / WebP | 覆盖手机相册与截图 |
| 原始大小上限 | 5 MB | 超过直接拒绝，不在前端解码大图（低端机会卡死） |
| 输出尺寸 | 256 × 256，正方形，居中裁切 | 头像最大显示 112px，2× 屏够用 |
| 输出格式 | JPEG，质量 0.82；含透明通道时用 PNG | 家庭照片以人像为主 |
| 典型体积 | 12–60 KB | 备份不会因头像膨胀 |
| 显示形态 | 圆形（`border-radius: 50%`），96/112px 两档 | 与身份选择头像墙一致 |
| 裁剪交互 | 拖动平移 + 双指/滑杆缩放（1×–3×），无旋转 | 够用且好实现 |

### 7.3 校验与失败（每一条都必须有文案，不许静默）

| 情况 | 提示 | 原头像 |
|---|---|---|
| 格式不支持 | 这张图打不开，换一张 JPG 或 PNG 试试 | 保留 |
| 超过 5MB | 这张图超过 5MB，换一张小一点的 | 保留 |
| 读取失败 / 图片损坏 | 这张图读不出来，换一张试试 | 保留 |
| 存储空间不足 | 这台设备存不下了，先导出备份清点空间 | 保留 |
| 用户取消选图 | 无提示，直接回到选择层 | 保留 |
| 保存事务失败 | 这次没保存成功，再点一次 | 保留 |

### 7.4 多孩隔离与删除

- 头像按 `childId` 存，孩子 A 换头像不影响 B；
- 删除孩子（本版无删除入口）或彻底清空家庭数据时，头像图片必须**一并删除**，不留孤儿数据；
- 导入备份恢复后，头像必须回来（备份里要带图片本体，不能只存 `blob:` URL）。

### 7.5 存储方案建议（不替 Trae 决定）

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A（建议）** | `children` 上加一个可空字段存 dataURL 字符串 | 零迁移、备份天然带上、清空一并清、查询简单 | 单行变大（约 30KB），Dexie 读写略慢 |
| B | 新表 `childAvatars { childId, blob, mime, w, h }` | `children` 行保持轻 | 需要 Schema 升版与迁移；备份要处理 Blob；清空要多清一张表 |

家庭场景孩子数通常 < 5、头像总量 < 300KB，**A 的代价可以忽略**。若 Trae 选 B，只要满足 §7.4 的三条不变量即可，设计侧不干预。

### 7.6 与备份的关系（必须核对，不许假装已支持）

现有备份是按表导出的 JSON。头像若为 dataURL 会被自然带上；若为 Blob，JSON 序列化会**丢失或变成 `{}`**。这是本轮最需要 Trae 确认的一点，已在 `05` §8.2 列为 **Q-M6-01（阻塞开发，不阻塞设计）**。

界面侧不因这个未决项而改设计；但备份成功提示里**不得**出现"包含头像"之类承诺，直到实现侧确认。

## 9. 本轮明确未做（D3）

- 五种宠物 × 7 级 = 35 套等级形态；
- 宠物待机/呼吸动画（`04` §9 原本就禁止循环动效）；
- 头像旋转、滤镜、贴纸、相册多选；
- 头像云端存储（本产品无后端）；
- 宠物"性格/亲密度/喂食"等新养成维度；
- 宠物切换的过场动画（切换后直接刷新即可）。
